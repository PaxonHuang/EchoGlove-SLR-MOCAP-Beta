## 1 项目愿景与迁移决策

### 1.1 项目愿景

EchoGlove 是一款基于端云协同双层级推理的智能数据手套，旨在实现实时手语翻译与 3D 手部动作捕捉。系统采用 L1（边缘端）+ L2（云端）双层推理架构，通过置信度驱动路由在两层之间智能调度。L1 层在 ESP32-S3 上运行 1D-CNN+Attention 模型（34K 参数，INT8 量化），实现 <5ms 推理延迟；L2 层在 Python Relay 服务器上运行 ST-GCN 模型（280K 参数），处理复杂手语序列。

项目五大核心目标：

1. **实时性能**：L1 推理 <5ms，端到端 L1 路径 <50ms
2. **准确率**：L1 >90% Top-1（46 类），L2 >95% Top-1
3. **低成本**：BOM ~$46（国产 Flex）至 ~$81（Spectra Symbol）
4. **低功耗**：>12h 电池续航（600mAh LiPo）
5. **双向翻译**：手语→文本（NLP 语法纠正 + TTS）和 文本→手语（3D 手部动画）

### 1.2 V3.0→V4.0 迁移决策背景

V3.0 架构采用 BNO085 IMU + 5×TMAG5273 Hall 传感器 + 5×N52 钕磁铁方案。经过深入分析和全球文献调研，确认该架构存在以下致命问题：

| 问题 | 严重程度 | 详细说明 |
|------|----------|----------|
| BNO085 磁力计干扰 | **致命** | 5 颗 N52 钕磁铁在 BNO085 位置叠加磁场 ~5-10 Gauss，远超地磁场(0.25-0.65G)，完全淹没地磁信号 |
| Hall 传感器串扰 | **严重** | 相邻手指磁铁对 TMAG5273 的交叉干扰，食指-中指间距仅 ~2-3cm |
| 非线性响应 | **严重** | 磁场 1/r³ 衰减导致弯曲角度映射极其困难，每次佩戴需重新标定 |
| 无文献先例 | **致命** | 全球无任何已发表文献成功在同一手套上同时使用 Hall+磁铁+9 轴 IMU |
| 学术可信度风险 | **严重** | 审稿人必将质疑磁场干扰问题，影响论文发表 |

**定量分析**：N52 3mm×1mm 钕磁铁表面磁场约 2,500 Gauss，在 5cm 处衰减至 ~2-3 Gauss（仍大于地磁场 0.25-0.65G），5 颗磁铁叠加在 BNO085 位置产生 ~5-10 Gauss，完全超出 BNO085 磁力计 ±8 Gauss 量程的有效工作范围。磁场按 1/r³ 衰减，即使手指间距仅 2-3cm，相邻磁铁的交叉干扰也足以严重影响相邻 TMAG5273 的读数。

基于以上分析，决定全面迁移至 **IMU(BNO085) + 5×弯曲传感器(SpectraFlex 2.2") + 2×ADS1115 ADC** 架构。该方案是全球手语识别数据手套领域最广泛验证的架构，在已发表文献中达到 95-99% 的 SLR 准确率。迁移不影响项目的核心创新点，反而通过更清洁的传感器数据提升系统整体可靠性。

### 1.3 核心创新点保护分析

| 创新点 | 是否依赖 Hall 传感器 | 迁移后状态 |
|--------|---------------------|------------|
| 双层级推理(L1/L2) | 否 | **完全保留** — 这是最大创新 |
| 置信度驱动路由 | 否 | **完全保留** |
| ST-GCN 伪骨骼映射 | 部分依赖 | **需适配但更自然**（Flex 直接给弯曲角度） |
| CSL NLP 语法纠正 | 否 | **完全保留** |
| TTS 双向翻译 | 否 | **完全保留** |
| 3D 骨骼渲染 | 部分依赖 | **更简单**（Flex→角度直射） |

**迁移后新增创新点**：

1. **低维特征下的高效推理**：从 21 维 Hall 特征降至 11 维 Flex+IMU 特征，在更低维度下达到同等精度，证明模型效率
2. **弯曲传感器到伪骨骼的新映射范式**：需要新的特征工程和伪骨骼映射策略，这本身就是创新
3. **简化硬件下的完整端云系统**：更低的 BOM、更简洁的硬件，但功能不减反增
4. **跨传感器架构的模型迁移学习**：如果设计一套与传感器无关的特征抽象层，则是真正的架构创新

### 3.2 V4.0 硬件架构

| 组件 | 型号 | 数量 | I2C 地址 | 职责 |
|------|------|------|----------|------|
| MCU | ESP32-S3-DevKitC-1 N16R8 | 1 | — | 双核 240MHz, 8MB PSRAM |
| IMU | GY-BNO085 (7Semi) | 1 | 0x4B | 9-DOF, Game Rotation Vector |
| ADC #1 | ADS1115 (ADDR=GND) | 1 | 0x48 | 16-bit, 4 通道读 Flex1-4 |
| ADC #2 | ADS1115 (ADDR=VDD) | 1 | 0x49 | 16-bit, 1 通道读 Flex5 |
| Flex 传感器 | SpectraFlex 2.2" (或国产替代) | 5 | — | 手指弯曲角度检测 |

### 3.3 I2C 总线拓扑 (V4.0 简化后)

V4.0 架构的 I2C 总线大幅简化：移除 TCA9548A I2C Mux 后，所有设备直接挂载在同一 I2C 总线上。GPIO 8(SDA)/GPIO 9(SCL)，400kHz Fast Mode。总线上仅有 3 个设备：BNO085(0x4B)、ADS1115 #1(0x48)、ADS1115 #2(0x49)，地址无冲突，无需多路复用器。上拉电阻统一为 4.7kΩ。这种简化消除了 TCA9548A 通道切换的 1ms 延迟和单点故障风险。

### 3.4 弯曲传感器电路设计

每个弯曲传感器采用电压分压电路：传感器串联 10kΩ 下拉电阻接至 3.3V，ADS1115 读取分压中点电压。当传感器平直时电阻约 10kΩ，分压输出约 1.65V；弯曲时电阻升至约 125kΩ，分压输出约 2.94V。动态范围约 1.29V，ADS1115 的 16-bit 分辨率在 ±4.096V 量程下提供约 0.125mV 分辨率，远超需求。PGA 增益可设为 ±2.048V 以获得更高精度。

### 3.5 特征向量定义 (V4.0)

| 特征组 | 数量 | 来源 | V3.0 对比 |
|--------|------|------|-----------|
| Flex (5 指弯曲角度) | 5 | ADS1115 × 2 | 0 (Hall 15→5) |
| 欧拉角 (roll, pitch, yaw) | 3 | BNO085 (GRV) | 3 (不变) |
| 角速度 (x, y, z) | 3 | BNO085 (Calibrated) | 3 (不变) |
| **活跃特征总数** | **11** | | **21 (减半)** |
| **滑动窗口** | **30×11 = 330** | | **30×21 = 630** |

特征维度从 21 降至 11，模型输入从 630 维降至 330 维。这对模型设计和训练有重要影响，但同时也意味着更小的模型和更快的推理。关键变化是将 Hall 传感器的 3 轴磁场强度（非线性、有串扰）替换为弯曲传感器的 1 维弯曲角度（线性、直觉），这使得特征工程更简单，模型训练更容易收敛。

## 4 Phase 1 — HAL 与驱动层 (V4.0)

### 4.1 ADS1115 ADC 驱动

采用 Adafruit ADS1X15 库作为基础，封装 ADS1115Manager 类。每个 ADS1115 提供 4 路单端输入，2 片共计 8 路，使用其中 5 路连接 5 个弯曲传感器。ADS1115 #1（0x48）读取 Flex1-4，ADS1115 #2（0x49）读取 Flex5（A0 通道）。采样模式为单次触发转换，每次读取前发送 START 命令，等待转换完成后读取结果。采样率设置为 860SPS，5 通道轮询每通道约 172SPS，远超 100Hz 需求。PGA 增益设为 ±2.048V，对准 1.29V 动态范围提供最佳分辨率。

**ADS1115Manager 接口设计**：

```cpp
class ADS1115Manager {
public:
    bool begin();                      // 初始化两片ADS1115
    float readChannel(uint8_t adc, uint8_t ch);  // 读单通道电压
    void readAll(float out[5]);        // 读取5个Flex值
    void setPGA(gain_t gain);          // 设置PGA增益
    void calibrate();                  // 2秒flat-position校准
private:
    Adafruit_ADS1115* ads1;            // 0x48
    Adafruit_ADS1115* ads2;            // 0x49
};
```

### 4.2 FlexManager 实现 (V4.0 激活)

V3.0 中 FlexManager 仅为占位符（返回全零），V4.0 需完全实现。核心职责是将 ADS1115 原始 ADC 值转换为 0-1 范围的归一化弯曲角度。转换流程：ADC 原始值(16-bit 有符号整数) → 电压(mV) → 电阻(kΩ) → 弯曲角度(°) → 归一化[0,1]。其中电阻到角度的映射采用查表法，通过 2 秒校准流程获取每个传感器的 flat/max 基准值。

**FlexManager 核心逻辑**：

```cpp
class FlexManager {
public:
    void begin(ADS1115Manager* adc);
    void readAll(float normalized[5]);  // 输出[0,1]归一化弯曲角度
    void calibrate();                   // 2秒校准
    bool isCalibrated() const;
private:
    ADS1115Manager* _adc;
    float _flatBaseline[5];   // 伸直时ADC值
    float _bentBaseline[5];   // 弯曲时ADC值
    bool _calibrated;
};
```

### 4.3 BNO085 驱动（不变）

BNO085 继续使用 SH2_GAME_ROTATION_VECTOR 模式（6 轴融合），100Hz 输出四元数和角速度。该模式完全不使用磁力计，免疫磁场干扰。代价是 yaw 方向漂移 1-5°/分钟，但对于手语识别场景（主要关注相对姿态而非绝对航向），这一漂移在可接受范围内。可考虑通过已知姿态（如双手自然下垂）定期校准 yaw。

### 4.4 SensorManager 改造

SensorManager 从管理"I2C Mux + 5×TMAG5273 + 1×BNO085"简化为"2×ADS1115 + 1×BNO085"。采样时序从"TCA9548A 通道切换 + TMAG5273 触发转换 + BNO085 读取"变为"ADS1115 #1 4 通道轮询 + ADS1115 #2 1 通道读取 + BNO085 读取"。采样延迟从约 10ms 降至约 6ms（5 路 ADS1115 轮询约 5ms + BNO085 约 1ms），整体采样率可提升至 150Hz+。仿真模式仍保留，用于无硬件时的管线测试。

### 4.5 FreeRTOS 任务架构

| 任务 | 核心 | 优先级 | 频率 | 栈 | 职责 |
|------|------|--------|------|----|------|
| Task_SensorRead | 1 | 3 | 100Hz | 4096 | ADS1115+BNO085 采样 + Kalman |
| Task_Inference | 0 | 2 | ~30Hz | 8192 | L1 模型推理 |
| Task_Comms | 0 | 1 | 100Hz | 8192 | BLE 配网 + UDP 发送 |

## 5 Phase 2 — 信号处理 (V4.0)

### 5.1 Kalman 滤波器

Kalman 滤波通道数从 21 降至 11：5 路 Flex + 3 路欧拉角 + 3 路角速度。计算量减少约 48%，释放 CPU 时间。Flex 传感器的噪声特性与 Hall 传感器不同，需重新调整 Q/R 参数。初始建议：Flex 通道 Q=0.001（低过程噪声，传感器稳定）、R=0.05（低测量噪声，ADS1115 16-bit 精度）；IMU 通道保持原参数 Q=0.01、R=0.1。实际参数需根据采集数据统计优化。

### 5.2 滑动窗口

SlidingWindow 从 30×21 变为 30×11，PSRAM 占用从约 25KB 降至约 13KB。环形缓冲区 SPSC 架构不变，仅调整 FEATURE_DIM 常量。这释放的 PSRAM 可用于未来扩展（如增加压力传感器或更大的窗口尺寸）。

### 5.3 特征归一化

Min-Max 归一化仍采用 [0,1] 区间映射，但通道数从 21 减至 11。校准流程仍为 2 秒，但 Flex 通道的校准方式不同：用户需依次伸直和弯曲每根手指，记录 flat 和 bent 基准值。这比 Hall 传感器的校准更直观、更可重复，因为弯曲角度与电阻的关系是单调的，不像磁场与距离的 1/r³ 非线性关系。

## 6 Phase 3 — L1 边缘推理 (V4.0)

### 6.1 L1 模型架构调整

L1 模型输入从 30×21=630 维降至 30×11=330 维。模型 A（1D-CNN + Attention）需调整第一层 Conv1d 的输入通道数从 21 至 11。由于输入维度减半，模型参数量可从 34K 降至约 20K，推理速度更快。TFLite Micro 的 Tensor Arena 从 80KB 可缩小至约 50KB，释放更多 PSRAM。

### 6.2 训练路径

仍采用双路径：路径 A 为 Edge Impulse 快速原型（2-3 天），路径 B 为 PyTorch 自定义训练（更高精度）。Edge Impulse 支持直接导入 11 维特征的时间序列数据，仅需在数据采集时将输出格式从 21 列改为 11 列。训练数据需全部重新采集，这是迁移的最大工作量。建议采集流程：每个手势采集 10 次重复，46 个手势×10 次 = 460 次采集，每次约 3 秒，总采集时间约 23 分钟。

### 6.3 模型基准评估

Phase 3.5 基准评估仍采用 5-fold stratified cross-validation，评估指标为 Top-1、Top-5、FLOPs、延迟、参数量、模型大小。由于输入维度减半，基准评估应特别关注准确率是否受影响。如果 11 维特征达到 21 维特征同等准确率，则证明了弯曲传感器提供的信息更精炼有效。

## 7 Phase 4 — 通信协议 (V4.0)

### 7.1 Protobuf 消息格式更新

原 V3.0 Protobuf 已预留 flex_features 字段，V4.0 仅需将 hall_features 清零、flex_features 激活：

```protobuf
message GloveData {
  uint32 timestamp = 1;
  repeated float hall_features = 2;   // 15→0 floats (V4.0清零)
  repeated float imu_features = 3;    // 6 floats (不变)
  repeated float flex_features = 4;   // 0→5 floats (V4.0激活)
  uint32 l1_gesture_id = 5;
  uint32 l1_confidence_x100 = 6;
  bool l2_requested = 7;
  string status = 8;
}
```

这是迁移的重大好处：Protobuf 协议已预留 flex_features 字段，无需修改 .proto 定义。仅需在固件端将 SensorData.toProtobuf() 中的填充逻辑从 hall→flex 切换即可。总 payload 从 26 floats 降至 16 floats，UDP 帧大小减少约 40 字节，进一步降低 WiFi 吞吐压力。

### 7.2 WebSocket JSON 格式更新

Relay→前端的 WebSocket JSON 格式需更新：将 hall 数组替换为 flex 数组。Zustand 的 useSensorStore 也需相应调整：从 15 floats (hall) + 6 floats (imu) 变为 5 floats (flex) + 6 floats (imu)。这是一个纯格式变更，不影响业务逻辑。

## 8 Phase 5 — Python Relay 与 L2 推理 (V4.0)

### 8.1 ST-GCN 伪骨骼映射重设计

这是 V4.0 迁移中最关键的模型层变更。原 V3.0 的 ST-GCN 通过 Linear(21→42) 将 21 维传感器特征映射为 21 个伪 2D 关键点，V4.0 需重新设计该映射层。推荐三种方案：

| 方案 | 映射策略 | 优势 | 创新度 |
|------|----------|------|--------|
| 方案 A: 运动学链推算 | Flex→5 MCP 角度, IMU→腕旋转, 中间节点插值 | 最符合生物力学, 可解释 | ★★★ |
| 方案 B: 可学习特征提升 | Linear(11→42) 可训练映射 | 自适应特征空间 | ★★★★ |
| **方案 C: 混合映射** | **Flex→MCP, 其余节点学习插值** | **兜底与可学习结合** | **★★★★★** |

**推荐采用方案 C（混合映射）**：5 个 Flex 值直接赋给 21 节点图中的 5 个 MCP 关节节点（拇指节点 1、食指节点 5、中指节点 9、无名指节点 13、小指节点 17），BNO085 四元数赋给腕节点 0。其余 15 个节点通过一个可训练的 Feature Lifting 层（Linear(11→21×2=42)）学习插值。这种混合方案兜底了物理约束（MCP 节点直接从 Flex 获取真实弯曲角度）和学习能力（中间节点通过训练学习最优插值），是最具创新性的方案。

### 8.2 图拓扑与邻接矩阵（不变）

21 节点的手部骨骼拓扑和邻接矩阵在 V4.0 中完全不变。节点定义仍为：Wrist(0)→Thumb(1-4)、Index(5-8)、Middle(9-12)、Ring(13-16)、Pinky(17-20)，掌骨横链(5,9)、(9,13)、(13,17)。GraphConv 中的 3 类邻接矩阵（self、forward、backward）和 D^(-1/2)AD^(-1/2) 归一化也不变。仅仅输入特征的维度和映射方式发生变化。

### 8.3 NLP 与 TTS（不变）

CSL→普通话语法纠正引擎、edge-tts 语音合成、置信度路由器等组件完全不受传感器架构变更影响。这些组件位于手势分类之后的下游，其输入仅为手势 ID 和置信度，与传感器类型无关。

## 9 Phase 6 — 渲染 (V4.0)

### 9.1 React + R3F 3D 手部渲染

V4.0 中 3D 渲染变得更简单。原 V3.0 需要从 15 维 Hall 磁场数据通过复杂的非线性映射推算弯曲角度，V4.0 的 Flex 值本身就是归一化后的弯曲角度，可直接用于驱动骨骼旋转。useHandAnimation hook 的映射逻辑大幅简化：5 个 Flex 值直接映射到 MCP 关节旋转，中间节点（PIP/DIP）用 MCP 角度的 0.6 倍和 0.4 倍近似。BNO085 四元数直接应用于腕节点旋转。这种简化使得渲染更流畅、调试更容易。

**Flex→骨骼角度映射规则**：

```
Flex[i] → MCP[i] 旋转角度 = Flex[i] × 90°  (归一化值×最大弯曲角)
MCP[i]  → PIP[i] 旋转角度 = MCP[i] × 0.6   (运动学近似)
MCP[i]  → DIP[i] 旋转角度 = MCP[i] × 0.4   (运动学近似)
BNO085  → Wrist 旋转       = 四元数直接应用
```

### 9.2 Unity ms-MANO 参数映射

Unity 层的 ms-MANO 参数化手模型（48 DOF: 3 wrist + 15 joints × 3）的参数映射也变得更自然。原 V3.0 的 Hall 磁场数据需要复杂的非线性反解才能转换为 MANO 参数，V4.0 的 Flex 弯曲角度可直接映射为 MANO 的关节旋转参数。CustomHandDataProvider 需调整解析逻辑，从解析 Hall 特征改为解析 Flex 特征，但映射关系更加简单直接。

## 14 全球方案对比与技术选型依据

### 14.1 六大架构对比

| 架构 | 代表项目 | SLR 准确率 | 成本 | 可靠性 | 综合推荐 |
|------|----------|-----------|------|--------|----------|
| **IMU+Flex** | Burhani 2023; MDPI 2024 | 95-99% | $50-100 | 极高 | **最推荐** |
| IMU+Hall+磁铁 | Padhya 2025 | 96% | $80-100 | 中(串扰) | 有隐患 |
| 纯 IMU(多节点) | FSGlove 2025 | 高 | $200-400 | 中 | 昂贵复杂 |
| IMU+EMF | MANUS/Rokoko | 极高 | $2000-5000 | 极高 | 商业级 |
| 电容拉伸 | StretchSense | 极高 | $2500-5000 | 极高 | 专业 MOCAP |
| 纯视觉 | MediaPipe+论文 | 90-97% | $0 | 低 | 非穿戴 |

### 14.2 ADC 方案选型依据

| 方案 | 分辨率 | 通道 | 接口 | 优势 | 劣势 | 成本 |
|------|--------|------|------|------|------|------|
| CD74HC4067+ESP32 ADC | 12-bit | 16 | GPIO | 最便宜 | ESP32 ADC 非线性 | ~$2 |
| **2×ADS1115(推荐)** | **16-bit** | **8** | **I2C** | **高精度、无需 Mux** | **2 片 IC** | **~$6** |
| MCP3008 | 10-bit | 8 | SPI | 简单 | 仅 10-bit | ~$3 |
| 1×ADS1115+ESP32 ADC | 16+12-bit | 5 | I2C+ADC | 成本适中 | 精度不一致 | ~$4 |

最终选择 2×ADS1115 方案的核心理由：

1. 16-bit 分辨率为弯曲传感器 ±30% 容差提供充足余量做软件校准
2. 2 片 ADS1115 与 BNO085 共享同一 I2C 总线，地址无冲突（0x48/0x49/0x4B），无需 TCA9548A
3. 5 路全部走 ADS1115，代码统一无精度差异
4. 内置 PGA 和 ΔΣ 调制器，噪声远低于 ESP32 SAR ADC
5. 采样率 860SPS，5 通道轮询约 172SPS/通道，远超 100Hz 需求
