## D1: 硬件拓扑 — 2×ESP32-S3(手套) + 1×ESP32-P4(基站) + ESP32-C6(协处理器)

### 选项对比

| 维度 | A. 3×ESP32-S3（V5.1方案） | B. 2×S3+P4基站（V5.2 选中） | C. 全P4方案 |
|------|---------------------------|------------------------------|-------------|
| 手套端算力 | 240MHz 双核 | 240MHz 双核（同左） | 400MHz 双核（过强） |
| 基站端算力 | 240MHz | ✅ 400MHz + NPU (1.7×) | 400MHz + NPU |
| 显示输出 | ❌ 无 | ✅ 7" RGB LCD | ✅ 7" RGB LCD |
| 视觉输入 | ❌ 无 | ✅ MIPI-CSI 摄像头 | ✅ MIPI-CSI |
| 音频能力 | ❌ 无 | ✅ I2S + PDM 音频 | ✅ I2S + PDM |
| 无线方案 | ESP-NOW (S3内置) | ✅ ESP32-C6 协处理器 | ESP32-C6 协处理器 |
| USB 传输 | USB FS (12Mbps) | ✅ USB HS (480Mbps) | ✅ USB HS |
| 成本 | ~¥75 | ~¥130 | ~¥200+ |
| 功耗 | 中 | 中高 | 高 |
| 手套固件兼容 | ✅ 与V5.1一致 | ✅ 手套端不变 | ❌ 需重新开发 |

### ✅ 选择

**B. 2×ESP32-S3(手套) + 1×ESP32-P4(基站) + ESP32-C6(协处理器)**

### 核心依据

- **P4 提供 1.7× 算力提升**：双核 400MHz + 8MB PSRAM 内置 + 32MB PSRAM 外置，Tier2 增强模型可行
- **7" 显示屏**：竞赛现场实时展示识别结果、手势骨架、置信度，评委体验大幅提升
- **MIPI-CSI 视觉**：摄像头可作为手语识别的辅助模态（视觉+惯性融合方向）
- **音频 TTS**：手语识别结果可通过扬声器播报，实现手语→语音的完整链路
- **C6 协处理器**：ESP32-C6 独立处理无线通信（ESP-NOW + BLE 双模），不占用 P4 算力
- **手套端固件不变**：V5.1 的 ESP32-S3 手套固件完全兼容，零迁移成本

### 全链路影响

```
硬件层:
  手套L(ESP32-S3) → ESP-NOW → 基站(ESP32-C6接收 → UART → ESP32-P4推理)
  手套R(ESP32-S3) → ESP-NOW ↗

推理链:
  手套端: Tier1 (12节点ST-GCN ~50KB) → 本地粗分类
  基站端: Tier2 (增强版Gated Bi-CrossAttn ~120KB) → 双手协同识别
  PC端:   Tier3 (42节点ST-GCN ~300KB) → 精细识别+连续手语

展示链:
  P4推理 → 7"LCD实时展示 + 音频TTS播报 + USB HS → PC/VR

通信链:
  C6(ESP-NOW主通道) + C6(BLE 5.0备份) → 双模共存
```

- **手套固件**: 完全不变，Tier1 推理逻辑保持一致
- **基站固件**: 需全新开发 P4 固件（推理+显示+音频+USB HS）
- **C6 固件**: 需开发无线中继固件（ESP-NOW 接收 → UART 转发 → P4）
- **PC 端**: USB HS 接收，无需 WiFi，更稳定

### 🏷️ V5.2 变更标记

> 🔄 **V5.2 重大修改决策**
> V5.1 为 3×ESP32-S3（双手套+接收器），V5.2 将接收器升级为 ESP32-P4 智能基站 + ESP32-C6 无线协处理器，实现多模态展示和增强推理。手套端零变更。

## D2: 通信同步 — ESP-NOW 广播 + SYNC_TICK

### 选项对比

| 维度 | A. WiFi STA + UDP | B. ESP-NOW 广播 | C. BLE 5.0 | D. 2.4GHz 私有协议 |
|------|-------------------|-----------------|------------|---------------------|
| 延迟 | 5-20ms | 1-2ms | 7.5-30ms | <1ms |
| 配对 | 需 SSID/密码 | 免配对（MAC 绑定） | 需配对 | 需自定义 |
| 抗干扰 | 中 | 高（信道跳频） | 中 | 高 |
| 吞吐 | 高 | 中（250B/包） | 低 | 高 |
| 生态 | 完善 | ESP-IDF 原生 | 完善 | 需自研 |

### ✅ 选择

**B. ESP-NOW 广播 + SYNC_TICK**

### 核心依据

- 免配对：接收器上电即收，手套端 MAC 地址预置，零配置启动
- 1-2ms 端到端延迟，满足实时手势识别 < 50ms 总延迟预算
- SYNC_TICK 心包（每 10ms）实现中心化时钟同步，避免多手套冲突
- 广播模式天然支持一对多，接收器同时接收左右手数据
- V5.2 中由 ESP32-C6 协处理器接收，不占用 P4 算力

### 全链路影响

```
采样(100Hz) → SYNC_TICK对齐 → ESP-NOW广播(250B/包) → C6接收 → UART → P4解包 → 时间戳校验 → 帧缓冲 → 推理
```

- **时钟域**: 手套端以基站 SYNC_TICK 为参考时钟，漂移 < 0.5ms
- **丢包处理**: 需插值补帧（D19），WiFi 密集环境 1-5% 丢包率
- **带宽**: 每手套 ~2.5KB/s（11 维 × 4B × 100Hz ÷ 包头），远低于 ESP-NOW 上限
- **V5.2 变化**: ESP-NOW 接收端从 ESP32-S3 变更为 ESP32-C6，通过 UART 转发至 P4

### 🏷️ V5.2 变更标记

> — **V5.1 继承决策**
> V5.2 保持 ESP-NOW 协议不变，仅接收端硬件从 S3 变更为 C6（D22 关联）。

## D3: 特征向量 — 29-dim (11×2 + 相对7)

### 选项对比

| 维度 | A. 22-dim (11×2) | B. 28-dim (V5.1) | C. 29-dim (V5.2 选中) | D. 34-dim (11×2+12) |
|------|-------------------|--------------------|------------------------|---------------------|
| 双手关系 | ❌ 无 | ✅ 6 维相对特征 | ✅ 7 维相对特征 | ✅ 12 维相对特征 |
| 位置信息 | ❌ 无 | ❌ 无（相对推算） | ✅ UWB 距离标量 | ✅ 完整位置 |
| 计算量 | 低 | 中 | 中 | 高 |
| 手语表达力 | 低（单手） | 高（双手空间） | 极高（+距离约束） | 极高 |
| 模型参数 | 少 | 中 | 中 | 多 |
| 实时性 | 极好 | 好 | 好 | 一般 |

### ✅ 选择

**C. 29-dim = 11×2（每手）+ 7（相对特征）**

### 核心依据

- 双手手语的核心语义 = **空间关系**（如"大""小"的双手间距、方位）
- 相对 7 维设计（V5.1 的 6 维 + V5.2 新增 1 维）：
  - **间距 3 维** (Δx, Δy, Δz)：双手掌心欧氏距离分量
  - **方位 2 维** (azimuth, elevation)：右手相对左手的球面角
  - **角速度 1 维** (Δω)：双手旋转速率差
  - **UWB 距离 1 维** (uwb_distance)：🆕 DW3000 TWR 双手直线距离标量
- **UWB 距离的独特价值**：
  - 提供绝对距离约束，不受 IMU 积分漂移影响
  - DW3000 TWR 精度 ~5cm，远优于 IMU 推算的 ~20cm
  - 作为 EKF 观测修正量，显著提升双手位置估计精度
  - 维度增加仅 1 维（3.6%），但信息增益显著
- 相比 34-dim 节省 15% 维度，避免冗余（12 维中有 5 维与单手特征强相关）

### 全链路影响

```
每手11维 → 双手22维 → 相对特征计算(6维) + UWB TWR距离(1维) → 29维特征向量 → ST-GCN输入 → 推理
                                                                 ↑
                                                    DW3000(L) ←TWR→ DW3000(R) at 10-20Hz
```

- **传感器**: 每手需 Flex(5) + IMU(6) = 11 通道（不变）
- **UWB**: 每手套增加 1 个 DW3000 模块，TWR 测距 10-20Hz（D21）
- **计算**: 相对特征在基站端实时计算（7 次浮点运算/帧）
- **模型**: ST-GCN 输入通道从 28→29，首层卷积核微调
- **数据集**: 标注需包含双手同步数据 + UWB 距离同步

### 🏷️ V5.2 变更标记

> 🔄 **V5.2 修改决策**
> V5.1 特征向量为 28-dim（6 维相对特征），V5.2 增加 UWB 双手距离标量至 29-dim，首次引入绝对距离约束解决"位置黑洞"问题。

## D4: 传感器方案 — Flex + IMU（放弃霍尔效应）

### 选项对比

| 维度 | A. Flex + IMU | B. 霍尔 + IMU | C. Flex + 霍尔 + IMU |
|------|---------------|---------------|----------------------|
| 弯曲精度 | 高（电阻线性） | 中（非线性+温漂） | 极高（冗余） |
| 磁干扰 | ✅ 免疫 | ❌ 严重 | ❌ 部分免疫 |
| 成本/手 | ~¥180 | ~¥250 | ~¥350 |
| 成熟度 | 全球主流 | 小众 | 学术探索 |
| 延迟 | <1ms | <1ms | <1ms |
| 校准复杂度 | 低 | 高 | 极高 |

### ✅ 选择

**A. Flex 传感器（5 根手指）+ IMU（手背 BNO085）**

### 核心依据

**Flex 是全球手部追踪成熟方案**：Shadow Robot Hand、Manus Prime、StretchSense 均采用 Flex 方案，产业验证充分。

**放弃霍尔效应的详细原因**：

| 问题 | 详情 |
|------|------|
| 磁源叠加 | 5 个 N52 磁珠（每指 1 个）在 3cm 处仍有 5-15mT，互相交叉叠加 |
| 灵敏度过高 | TMAG5273 灵敏度 1.67 LSB/mT，5 源叠加导致信号饱和 |
| 温漂 | 霍尔传感器 ~0.1%/°C，手指活动温差 5-15°C |
| 校准难度 | 5 源磁场解耦需要复杂的空间校准算法 |
| 成本 | 每指 1 磁珠+1 霍尔芯片 = ~¥50/指，5 指 = ¥250 |

**V5.2 补充说明**：DW3000 UWB 模块工作在 6.5-8 GHz 频段，与 Flex 电阻式传感器和 BNO085 IMU 无任何电磁干扰，完全兼容。

### 全链路影响

```
Flex(5×ADC) + BNO085(I2C) + DW3000(SPI) → 11维/手 + UWB距离 → 特征提取 → 推理
```

- **PCB**: 每手套 5 路 ADC（Flex）+ 1 路 I2C（BNO085）+ 1 路 SPI（DW3000），布线需注意 SPI 走线
- **固件**: 无需磁场解耦算法，降低手套端计算负担
- **校准**: 仅需 Flex 线性标定 + IMU 姿态校准 + UWB 天线延迟校准
- **可靠性**: 无磁源依赖，不受外部磁场（手机、音箱、金属桌面）干扰

### 🏷️ V5.2 变更标记

> — **V5.1 继承决策**
> V5.1 已彻底放弃霍尔效应，V5.2 继续沿用 Flex+IMU 方案。V5.2 新增 DW3000 UWB 模块（D21），与现有传感器无干扰。

## D5: BNO085 模式 — GRV 6 轴（不启用磁力计）

### 选项对比

| 维度 | A. IMU 9 轴（含磁力计） | B. GRV 6 轴（无磁力计） | C. 纯陀螺仪 3 轴 |
|------|-------------------------|-------------------------|-------------------|
| 绝对朝向 | ✅ 有（磁北参考） | ❌ 无（相对姿态） | ❌ 无 |
| 磁干扰 | ❌ 严重 | ✅ 免疫 | ✅ 免疫 |
| 漂移 | 低 | 中（需定期校正） | 高 |
| 计算量 | 高 | 中 | 低 |
| 手语适用性 | 低（手部磁场复杂） | 高 | 低 |

### ✅ 选择

**B. GRV（Game Rotation Vector）6 轴模式**

### 核心依据

- 室内环境磁干扰不可控：显示器、金属桌面、手机、音箱均为磁源
- 手部动作快速旋转时，磁力计数据滞后且噪声大
- GRV 仅使用加速度计 + 陀螺仪融合，BNO085 硬件级四元数输出
- 手语识别关注**相对姿态变化**而非绝对朝向，GRV 完全满足
- **V5.2 补充**：绝对位置信息由 UWB TWR + IMU EKF 融合提供（D21），弥补 GRV 缺失的绝对参考

### 全链路影响

```
BNO085(GRV模式) → 四元数(4D) + 加速度(3D) → 7D → 取6D(去除冗余w) → 11维特征的一部分
                                                        ↓
                                              EKF融合 ← DW3000 UWB距离
```

- **姿态**: 输出相对姿态，无磁北参考，适合室内场景
- **位置**: V5.2 通过 UWB+IMU EKF 提供 3D 位置估计（D21），弥补 GRV 无绝对位置
- **漂移**: 长时间使用需通过手势静止期自动校正（D18 关联）
- **功耗**: GRV 模式比 9 轴融合功耗低 ~30%

### 🏷️ V5.2 变更标记

> — **V5.1 继承决策**
> V5.1 已明确禁用磁力计，V5.2 继续沿用 GRV 6 轴。V5.2 通过 UWB+IMU EKF（D21）补充绝对位置信息。

## D6: I2C 策略 — 100kHz 全局降速

### 选项对比

| 维度 | A. 400kHz 标准 | B. 100kHz 降速 | C. 多总线分段 |
|------|---------------|----------------|---------------|
| 速率 | 400kbps | 100kbps | 400kbps/段 |
| 稳定性 | 中（6 设备易冲突） | 高 | 高 |
| 布线复杂度 | 低 | 低 | 高（多路复用） |
| 实时性 | 好 | 够用（100Hz 采样） | 好 |

### ✅ 选择

**B. 100kHz 全局降速**

### 核心依据

- 单手 6 个 I2C 设备（5×Flex ADC + 1×BNO085），共总线
- 100kHz 下总线容性裕度大，信号完整性好
- 11 通道 × 100Hz × 16bit = 17.6kbps，100kHz 总线带宽完全充足
- 稳定性优先：I2C 仲裁失败代价远大于速率收益
- **V5.2 补充**：DW3000 UWB 模块走 SPI 总线（非 I2C），不影响现有 I2C 策略

### 全链路影响

```
I2C@100kHz → 6设备轮询 → 采样延迟 ~1.5ms → 100Hz帧率不受影响
SPI@20MHz → DW3000 TWR → 10-20Hz测距 → 与I2C独立
```

- **延迟**: 单次 I2C 传输 ~0.2ms，6 设备轮询 ~1.2ms，可接受
- **固件**: 无需 I2C 多路复用器，代码简洁
- **可靠性**: 总线错误率从 400kHz 的 ~0.1% 降至 < 0.001%
- **UWB**: DW3000 通过 SPI 连接，与 I2C 总线完全隔离

### 🏷️ V5.2 变更标记

> — **V5.1 继承决策**
> V5.1 已验证 100kHz 稳定性，V5.2 继续沿用。DW3000 走 SPI 不影响 I2C 策略。

## D7: ST-GCN 分层 — Tier1/2 用 12 节点，Tier3 用 42 节点

### 选项对比

| 维度 | A. 全部 12 节点 | B. 全部 42 节点 | C. 分层（选中） |
|------|-----------------|-----------------|-----------------|
| 边缘计算量 | 极低 | 极高（不可行） | 低 |
| 精度 | 中 | 高 | 高（分层） |
| 参数量(12N) | ~50KB | N/A | ~50KB |
| 参数量(42N) | N/A | ~300KB | ~300KB |
| 适用场景 | 移动端 | PC 端 | 全场景 |

### ✅ 选择

**C. 分层 — Tier1/2: 12 节点, Tier3: 42 节点**

### 核心依据

**12 节点图**：
- 节点：每手 5 指尖 + 1 掌心 = 6 节点 × 2 手 = 12 节点
- 边：22 条（10 内手边 + 6 跨手边 + 6 自环）
- 精度：指尖位置建模充分，满足实时分类需求
- V5.2 增强：跨手边可利用 UWB 距离信息加权

**42 节点图**：
- 节点：每手 21 关节 × 2 手 = 42 节点（完整 MANO 关键点）
- 边：66 条（40 内手边 + 6 跨手边 + 20 自环）
- 精度：完整关节信息，支持细粒度手语识别

| 层级 | 节点数 | 边数 | 运行位置 | 用途 | V5.2变化 |

### 选项对比

### ✅ 选择

**B. 增强版 — Gated Bi-CrossAttn + MS-TCN 2-stage (~120KB)**

### 核心依据

- **ESP32-P4 算力释放**：双核 400MHz + 32MB PSRAM，相比 S3 的 240MHz + 512KB SRAM：
  - 计算力提升 1.7×，内存提升 64×
  - 120KB 模型仅占 PSRAM 的 0.375%，充裕
- **MS-TCN 2-stage 价值**：
  - Stage1：粗分类帧级预测
  - Stage2：精修边界 + 平滑预测
  - 相比无时序建模（V5.1），精度预计提升 3-5%
- **延迟可接受**：P4 上 ~30ms，仍在 100ms 实时预算内（手套→基站→推理总链路 ~35ms）
- **渐进升级路径**：2-stage → 4-stage 可后续升级，架构兼容

### 全链路影响

```
Tier1输出(12-dim) → Gated Bi-CrossAttn(空间融合) → MS-TCN Stage1(粗分类) → MS-TCN Stage2(精修) → Tier2输出
```

- **训练**: 需训练 CrossAttention + 2-stage MS-TCN，收敛策略：先 CrossAttn，后 MS-TCN
- **部署**: 量化后 ~60KB（FP16+INT8 混合，D20），P4 OTA 升级友好
- **延迟预算**:

  ```
  手套端采样: ~1ms
  ESP-NOW传输: ~2ms
  C6→P4 UART: ~1ms
  P4推理: ~30ms
  USB HS→PC: ~1ms
  ──────────────
  总延迟: ~35ms < 100ms ✅
  ```
- **后续**: V6 可在 P4 上追加 MS-TCN 3-4 stage，或扩展模型宽度

## D9: CrossAttention 变体 — Gated Bidirectional

### 选项对比

| 维度 | A. 标准 CrossAttn | B. Gated Bidirectional | C. Multi-Head CrossAttn |
|------|-------------------|------------------------|-------------------------|
| 空闲手处理 | ❌ 噪声注入 | ✅ 门控抑制 | ❌ 噪声注入 |
| 参数量 | ~4K | ~8K | ~16K |
| 精度提升 | +1.5% | +2.27% | +2.5% |
| 计算量 | 低 | 中低 | 中 |

### ✅ 选择

**B. Gated Bidirectional CrossAttention**

### 核心依据

- **门控机制**：sigmoid 门控自适应抑制空闲手（非主导手）的噪声贡献
- **双向注意力**：左手→右手 + 右手→左手，捕获双向空间关系
- **DGCA 论文**（WWW 2025）验证门控双向注意力在多模态融合中 +2.27% 精度
- **参数增量仅 8,256**：相比标准 CrossAttn 增加 ~4K 参数，可忽略
- **V5.2 增强**：门控值可与 UWB 距离联动——距离远时自动降低跨手注意力权重

### 全链路影响

```
左手特征(F_L) → Q_L, K_L, V_L ──┐
                                   ├→ Gated Bi-CrossAttn → 融合特征
右手特征(F_R) → Q_R, K_R, V_R ──┘
                                   ↑ UWB距离可调制门控值(V5.2增强)
```

- **门控值**: 接近 1 = 双手协同手势，接近 0 = 单手主导
- **推理**: 门控计算为逐元素 sigmoid，P4 上 < 0.2ms
- **可解释性**: 门控值可作为"双手协同度"指标，辅助调试
- **V5.2 增强**: UWB 距离标量可作为门控值的先验输入

### 🏷️ V5.2 变更标记

> — **V5.1 继承决策**
> V5.1 引入的门控双向注意力机制，V5.2 保持不变。V5.2 可选增强：UWB 距离调制门控值。

| 连续性 | 差（帧跳跃） | 好（平滑过渡） | 好 |
| 延迟 | 无额外 | 无额外 | 增加 RTT |
| 实现复杂度 | 低 | 中 | 高 |
| 适用丢包率 | <1% | 1-5% | >5% |

### ✅ 选择

**B. 线性插值补帧**

### 核心依据

- WiFi 密集环境（办公室、展会）ESP-NOW 丢包率 1-5%
- 线性插值：`x_t = x_{t-1} + (x_{t+1} - x_{t-1}) × Δt`，手势动作连续性好
- 无需重传，不增加延迟，适合实时场景
- 连续丢包 > 3 帧时触发降级提示
- **V5.2 补充**：UWB 距离数据为低频（10-20Hz），丢包时可用 IMU EKF 推算距离作为插值

- **精度损失**: < 0.5%（相比 FP32），门控层无损
- **部署**: 需 ESP-IDF 量化推理库支持混合精度
- **V5.2**: P4 的 FP16 加速单元使混合量化方案更具优势

  - TWR (Two-Way Ranging) 精度 ~5cm，满足双手距离测量需求

- **解决"位置黑洞"**：
  - V5.1 中双手相对位置完全依赖 IMU 积分推算，漂移严重
  - UWB 提供绝对距离标量，作为 EKF 观测修正量
  - EKF 融合：IMU 提供 100Hz 高频预测 + UWB 提供 10-20Hz 低频修正
- **创新性**：首次在手语手套项目中结合 UWB 测距与 IMU，学术与系统双重创新

### 全链路影响

```
DW3000(左手套) ←──TWR测距──→ DW3000(右手套)
       │ 10-20Hz                │
       ▼                        ▼
  SPI→ESP32-S3              SPI→ESP32-S3
       │                        │
       └──── ESP-NOW ────────→ C6 → UART → P4
                                       │
                    IMU数据(100Hz) ────→┤
                                       ▼
                               EKF 融合滤波器
                          ┌──────────────────┐
                          │ 预测步(IMU 100Hz) │
                          │ 更新步(UWB 10-20Hz)│
                          └──────────────────┘
                                       │
                                       ▼
                          3D位置估计(100Hz) + 距离标量
                                       │
                                       ▼
                          29-dim特征向量(D3) → ST-GCN推理
```

- **硬件**: 每手套增加 1 个 DW3000 模块（SPI 连接），PCB 需预留 UWB 天线区域
- **固件**: 手套端新增 DW3000 TWR 测距任务（独立线程，不干扰采样/推理）
- **基站端**: P4 运行 EKF 融合算法，输出 100Hz 3D 位置估计
- **特征**: UWB 距离标量 → 29-dim 特征向量的第 29 维（D3）
- **延迟**: TWR 测距 ~2ms，EKF 融合 ~0.5ms，总增加 < 3ms

### EKF 融合架构

```
状态向量: x = [px, py, pz, vx, vy, vz]  (3D位置 + 3D速度，双手各一组)

预测步 (IMU, 100Hz):
  x̂ₖ|ₖ₋₁ = F·x̂ₖ₋₁ + B·uₖ
  Pₖ|ₖ₋₁ = F·Pₖ₋₁·Fᵀ + Q

更新步 (UWB, 10-20Hz):
  z = ||p_L - p_R||  (UWB TWR 距离观测)
  Kₖ = Pₖ|ₖ₋₁·Hᵀ·(H·Pₖ|ₖ₋₁·Hᵀ + R)⁻¹
  x̂ₖ = x̂ₖ|ₖ₋₁ + Kₖ·(zₖ - h(x̂ₖ|ₖ₋₁))
  Pₖ = (I - Kₖ·H)·Pₖ|ₖ₋₁
```

### V5.1 → V5.2 变更驱动因素

```

ESP32-S3接收器无展示能力             → P4基站7"LCD实时展示(D22)
竞赛评审需要直观演示手段              → P4集成显示+音频+视觉(D22)
Tier2模型受S3算力限制(仅80KB)        → P4增强版120KB+MS-TCN(D8)
S3接收器无USB HS                    → P4 USB HS 480Mbps(D22)
ESP-NOW单通道不支持OTA              → BLE5.0备份通道(D23)
手机配对/调试需要                    → BLE GATT服务(D23)
```
